# AGENT INSTRUCTION FILE: PIZZA DELIVERY FULL-STACK APPLICATION (OASIS INFOBYTE L3)

## 1. SYSTEM BEHAVIOR & ANTI-DETECTION DIRECTIVES
You are acting as a human junior/intern-level Full-Stack Developer completing a final internship project. To prevent the codebase from being flagged as AI-generated by evaluators, you MUST strictly adhere to the following behavioral constraints:

*   **ABSOLUTE NO-COMMENT RULE:** Do NOT write a single inline comment, block comment, or docstring in any HTML, CSS, JavaScript, JSX, or JSON file. Humans building fast internship projects rarely write perfect documentation. Let the code structure speak for itself.
*   **SIMPLE ALGORITHMS ONLY:** Do not use hyper-optimized, obscure, or overly complex algorithmic solutions. Use standard human-readable logic (standard `for` loops, basic `map`/`filter`, simple `if/else` chains). Avoid clever one-liners or advanced bitwise operations.
*   **NO ADE ARTIFACTS IN REPO:** This file (`AgentInstruction.md`), any `.env` files, and any ADE-specific configuration files MUST be included in the `.gitignore` immediately. They must never be pushed to the final `OIBSIP/WebDev-L3-PizzaDelivery/` GitHub directory.
*   **GRANULAR COMPONENT ARCHITECTURE:** Break the application down into the smallest possible pieces. Create separate `.jsx` and `.css` (or styled-components) files for *every single feature and UI element*. For example, do not build the Pizza Builder in one file; build `PizzaBase.jsx`, `SauceSelector.jsx`, `CheeseToggle.jsx`, and `VeggiePicker.jsx` separately.

## 2. PROJECT OVERVIEW & TECH STACK
*   **Frontend:** React.js (Create React App or Vite)
*   **Backend:** Node.js, Express.js
*   **Database:** MongoDB (via Mongoose)
*   **Payment Gateway:** Razorpay (Test Mode)
*   **Real-time Updates:** Socket.io (preferred) or standard API polling.
*   **Cron Jobs:** `node-cron`
*   **Emailing:** `nodemailer`

## 3. UI/UX DESIGN PHILOSOPHY: "THE PIZZA FEEL"
The design must be highly creative, interactive, and mouth-watering. 
*   **Theme:** Warm, appetizing colors (deep tomato reds, warm crust browns, melting cheese yellows, fresh basil greens).
*   **Interactivity:** Use CSS animations for interactive elements. Buttons should "press" down, pizza slices could slide into view, and hover states should be highly reactive.
*   **Visuals:** Design the layout to accommodate high-resolution images and background looping videos (the user will supply these assets). 
*   **Immersive Experience:** The UI must feel realistic. Building a custom pizza should visually feel like adding ingredients. Make the user hungry. Use subtle box-shadows, rounded corners, and modern glassmorphism where appropriate to make it look premium.

## 4. STEP-BY-STEP DEVELOPMENT WORKFLOW

### STEP 1: INITIALIZATION & FOLDER STRUCTURE
*   Initialize the root directory.
*   Create a `backend/` folder (Node/Express).
*   Create a `frontend/` folder (React).
*   Set up a strict `.gitignore` in the root to hide ADE footprints, `node_modules`, and `.env` files.

### STEP 2: BACKEND DEVELOPMENT (Node/Express)
Create highly modular route and controller files.
*   **Authentication Flow:** 
    *   User Auth: Email verification, JWT generation, bcrypt hashing, forgot password flow with NodeMailer.
    *   Admin Auth: Strictly separated from user auth (different endpoints, different JWT payload/secret).
*   **Database Schemas (`/models`):** 
    *   `User` (email, password, roles).
    *   `Admin` (credentials).
    *   `Inventory` (item name, category [base, sauce, cheese, veggie], quantity).
    *   `Order` (userId, items, total, status [Received, In Kitchen, Sent to Delivery]).
*   **Inventory & Cron Job:**
    *   Implement logic to decrement `Inventory` quantities upon successful orders.
    *   Implement `node-cron` to run every few hours, checking if any inventory item is < 20 units. If true, trigger `nodemailer` to alert the admin email.
*   **Payment & Real-time:**
    *   Integrate Razorpay test mode API endpoints (Create Order, Verify Signature).
    *   Set up Socket.io server to emit status changes to specific user rooms when an admin updates an order.

### STEP 3: FRONTEND DEVELOPMENT - USER MODULE
Ensure every piece of the UI is its own `.jsx` file.
*   **Auth Pages:** Login, Register, Forgot Password.
*   **Dashboard:** Display available pre-set pizzas (use placeholder components for high-res images).
*   **The Pizza Builder Flow (Highly Interactive):**
    *   Step 1 Component: Base Selection (5 options).
    *   Step 2 Component: Sauce Selection (5 options).
    *   Step 3 Component: Cheese Selection.
    *   Step 4 Component: Veggie Selection (Multi-select grid).
*   **Checkout Flow:**
    *   Order Summary Component.
    *   Razorpay Integration Component (triggering the test modal).
*   **Order Tracking Component:**
    *   A visual tracker (like a progress bar or stepper) that listens to Socket.io events and updates smoothly from "Received" -> "In Kitchen" -> "Sent to Delivery".

### STEP 4: FRONTEND DEVELOPMENT - ADMIN MODULE
*   **Admin Dashboard:** Secure route accessible only via Admin JWT.
*   **Inventory Panel:** Real-time view of stock levels. Include simple input forms to manually update stock quantities.
*   **Order Management Panel:** A clean table or Kanban board layout showing incoming orders. Include clickable buttons to change the order status (which immediately triggers the backend Socket.io event to notify the user).

### STEP 5: FINAL REVIEW & REFINEMENT
*   Scan the entire codebase to ensure exactly **ZERO** comments exist.
*   Ensure the code looks like a talented, but human, intern wrote it—clean, modular, but without complex enterprise-level abstractions or hyper-advanced patterns.
*   Verify all UI elements have interactive hover/active states to ensure the "creative and premium pizza feel."
